# Stage 2: core daemon and ALSA plugin implementation plan

**Goal:** A daemon that owns one sound card, and an ALSA plugin installed as
`default`, so that ordinary ALSA players play through `aas`, mixed, resampled where
needed and bit-perfect where nothing alters the audio.

**Architecture:** The daemon has one real-time audio thread and one control thread.
The control thread owns the socket and every decision about rates. The audio thread
only executes those decisions. Everything that can be decided without a sound card
is pure Rust and tested on the workstation through a `Sink` trait. A client library
crate holds all plugin logic, so the ALSA plugin itself is a thin layer of FFI.

**Tech Stack:** Rust (edition 2024, `rust-version` 1.85), `alsa` 0.12, `libc`,
`rubato` 4, `rtrb` 0.4 for lock-free queues, `serde` with `toml` 1 for config and
state, `assert_no_alloc` 1 in tests.

**Spec:** `doc/design.md`. Measurements: `doc/measurements.md`.

## Stages

1. Measurement (done)
2. Core daemon and ALSA plugin (this plan)
3. Analog input, plugins, matrix, multiple outputs
4. API, monitoring, graph export
5. Packaging, Bluetooth and the switch from PipeWire, with all players tested

In this stage: one output, playback clients, mixing, the sample rate rules, the three

## Decisions this plan makes

These are not in the design. Task 12 adds them to it, marked *(call)*.

- **One latency rule replaces the period table.** The period is the largest power of
  two where 2 periods fit in the latency target, with a minimum of 32. A target of
  4 ms gives exactly the Pi 5 column and 12 ms exactly the Pi 3 column, at every rate.
  The default target is 4 ms on Pi 5 class boards and 12 ms on everything else.
- **The Pi 4 uses 12 ms until it is measured.** That is safe, not final.
- **The plugin converts to S32 stereo.** Conversion runs in the client's process, in
  its `transfer` callback, so it costs the audio thread nothing and the ring has one
  format. S16 and S24 shift left exactly. Mono is copied to both channels.
- **Without a card, audio goes to a timed null sink.** Players keep running in real
  time rather than hanging, while the daemon retries the card every second.
- **The control is called `Master`,** which `mpd.conf.default` already uses on device
  `default`. Its range is 0 to 100, linear in dB from -60 dB to 0 dB, and 0 mutes.
- **Fades last 10 ms and the settle time is 500 ms.**
- **Testing uses the test boards, not a VM.** Both boards can load `snd-aloop` and may
  be reinstalled, so a VM would add a step and prove nothing more.

## Global Constraints

- The audio thread does not allocate, take locks or make blocking calls during
  playback. Writing to the card is its only wait.
- A client can always connect. No client is ever refused, so nothing has a fixed limit.
- A stalled or crashed client loses only its own audio.
- The socket carries setup and teardown only. Audio never crosses it.
- The card runs at S32 whenever it supports it.
- Audio is never dithered. Float conversion scales by an exact power of two.
- Default processing format `f32`, resampling quality `high`.
- A wake-up gap longer than the buffer counts as a failure even with 0 xruns.
- Pass criterion: one hour at 44.1 kHz and at 96 kHz with no xruns and no such gap.
- Target: Debian trixie, 64-bit, aarch64. Standard `PREEMPT` kernel.
- The workstation has no ALSA headers. Anything linking ALSA builds on a test board:
  the feature `alsa-output` in `aas` and the crate `aas-alsa`, which stays out of the
  workspace's `default-members`.
- Public text names no internal hosts or addresses.

## Review Focus

1. The daemon dies while a client is blocked in `snd_pcm_writei`. The client must get
   an error, not hang. Task 10, `daemon_killed_during_write_returns_an_error`.
2. A client writes nonsense positions into shared memory. The daemon must clamp them
   and carry on. Task 1, `corrupt_positions_are_clamped`.
3. A DoP stream arrives with a volume or a fade pending. Not one altered sample may
   reach the card. Task 6, `first_dop_period_reaches_the_sink_unaltered`.
4. A player drains at the end of a track. Its last partial period must play in full.
   Task 7, `drain_plays_the_last_partial_period`.
5. A second client starts while the card is being reopened for the first.
   Task 7, `client_starting_during_reconfigure_loses_no_audio`.

- [ ] **Step 3: Implement `client.rs`, `control.rs` and `server.rs`**

The control thread polls the listener, the client sockets and a 50 ms timer, and
calls `RatePolicy::tick`. It builds every `Resampler`, `Source` and table, and frees
what comes back in events. When the audio thread gets `Reconfigure` it fades one
period, reopens the sink and stops reading sources until that finishes. No data is
lost, because the rings keep what clients write. Resamplers for the new rate are sent
before `Reconfigure`, in the same queue, so they take effect together.

The control thread owns the idle timer, since it already knows who is running. When
it expires it sends `CloseOutput`. The audio thread then closes the sink and parks,
and the control thread unparks it with the next `Reconfigure`.

### Task 10: ALSA PCM plugin

**Files:**

**Interfaces:**
- Consumes: `aas_client::client::Client`, `convert::ClientFormat`
- Produces: a `cdylib`, installed as `libasound_module_pcm_aas.so` in
  `/usr/lib/aarch64-linux-gnu/alsa-lib/`, exporting `_snd_pcm_aas_open` and
  `__snd_pcm_aas_open_dlsym_pcm_001`.
- `ffi.rs` declares `snd_pcm_ioplug_t` and its callbacks by hand, because `alsa-sys`
  does not cover them. Rust-only, as the design requires. `tests/layout.c` prints
  `sizeof` and `offsetof` from `alsa/pcm_ioplug.h`, and `tests/layout.rs` compiles it
  and compares them, so a mismatch fails the test instead of corrupting a player.
- Callbacks: `start`, `stop`, `pointer`, `transfer`, `close`, `hw_params`, `prepare`,
  `drain`, `delay`, `poll_descriptors_count`, `poll_descriptors`, `poll_revents`.
- Constraints offered: S16, S24, S24_3LE, S32, FLOAT, 1 or 2 channels, 8 to 384 kHz.
- Every callback runs inside `catch_unwind` and returns `-EIO` on a panic, so a bug
  here does not bring down a player.
- `poll_descriptors` returns both the wake eventfd and the socket. A hang-up on the
  socket makes `poll_revents` return `POLLERR` and `pointer` return `-ENODEV`.
- `pointer` returns `-EPIPE` once `underruns` has risen while running.
