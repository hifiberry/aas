# AES67 input and output (stage 1) Implementation Plan

**Goal:** `aas` receives one AES67 stream as a source in its mix and sends
what its master plays as an AES67 stream. Its time comes from a receive-only
PTP listener that runs beside `nqptp`.

**Architecture:** A new module `src/aes67/` with four threads:

- `aas-ptp`: the listener, behind a `PtpClock` that answers `now()`;
- `aas-sap`: SAP and SDP, the stream directory and our own announcement;
- `aas-aes67-in`: RTP in, then a jitter buffer, then `Adaptive`+`Drift`,
  then a ring;
- `aas-aes67-out`: monitor tap, then `Adaptive`+`Drift`, then RTP out.

The input enters the engine as a 48 kHz client `Source` named `aes67`,
tagged with a new matrix bus `Bus::Aes67`. Its volume, mute, rate handling
and bit-perfect rules are then the ones a player already has. The control
thread owns the lifecycle, the state file, the API and the ACR reports, as
for AirPlay.

**Tech Stack:** Rust. `std::net` and `libc` (an `AF_PACKET` socket, a
classic BPF filter, `SO_TIMESTAMPNS`, `IP_ADD_MEMBERSHIP`). The existing
`adaptive::Adaptive`, `drift::Drift`, `aas_client::ring::Ring`, and `ureq`
for ACR. No new crates.

**Spec:** `doc/plans/2026-11-23-aes67-design.md`. Approved by the owner
2026-11-23; stage 1 only.

## Global Constraints

- The audio thread never allocates, frees or locks (`engine.rs:1-5`).
  Everything AES67 does runs on its own threads, or on the control thread.
- `aas` sends no PTP packet, ever, in stage 1.
- The output sends nothing while `PtpClock::now()` is `None`.
- On the wire: 48 kHz; L24 or L16 big-endian. Input takes 1 to 8 channels
  and a packet time of at most 4 ms. Output is L24 stereo, 48 frames
  (1 ms) per packet.
- PTP group 224.0.1.129, ports 319 (event) and 320 (general). Domain from
  config, default 0. Two-step only.
- SAP 239.255.255.255:9875. Our announcement every 30 s, and a deletion on
  stop.
- A stream is forgotten after 10 announcement intervals without one, at
  most 3600 s.
- RTP timestamp = `(ptp_ns × 48000 / 10⁹ + mediaclk_offset) mod 2³²`. All
  PTP arithmetic is relative: Dante's timescale is arbitrary (≈57 years
  behind wall clock in the test), so never treat it as a date.
- PTP time is lost after 5 s without a Sync/Follow_Up pair; the input
  counts a stream as stopped after 1 s without a packet.
- Default latency: `"auto"` is 5 ms on a CM5 or Pi 5 (the model in
  `/proc/device-tree/model` contains `compute module 5` or `pi 5`), and
  20 ms on anything else. Configurable 1 to 100 ms.
- Output defaults: port 5004, TTL 16, name `"aas"`, group `"auto"`: 239.69.x.y
  with x, y the last two bytes of the interface's MAC; if y is 0 or 255 it
  becomes 1.
- Input and output threads run `SCHED_FIFO` 65 (as `further.rs`'s
  `WRITER_PRIORITY`). `aas-ptp` and `aas-sap` run at normal priority.
- Config errors read `aes67: <key> ...` and go through the existing
  file-name prefix (`config.rs:657`).
- Test fixtures and docs use placeholders (`192.0.2.x`, clock ID
  `00-11-22-ff-fe-33-44-55`, MAC `02:00:00:00:00:01`), never the owner's
  device data. Grep added lines for `192.168.` before every push.
- Format new files with `rustfmt --edition 2024 <file>`, never `cargo fmt`.
- Commits: conventional subjects, scope `aes67`. No tooling attribution in
  any commit, PR or comment.

## Review Focus

1. **A Dante grandmaster that restarts or hands over to another device.**
   The listener follows the new best master within one Announce interval;
   input re-anchors with a short silence, and output re-announces with the
   new `ts-refclk`. Test in Task 3
   (`a_better_master_takes_over_and_the_old_one_expires`) and Task 10
   (`a_new_grandmaster_restarts_the_input`).
2. **RTP timestamps that wrap at 2³²** in the middle of a jitter buffer or
   a drift measurement. Ordering and arithmetic stay right. Tests in Task 6
   and Task 7.
3. **A selected stream that disappears** (flow removed in Dante
   Controller, or the SAP deletion arrives) while it plays. The source plays
   silence, the API says `receiving: false`, and selecting it again after it
   reappears works without a restart. Test in Task 11
   (`a_withdrawn_stream_stays_selected_and_resumes`).
4. **The master changing rate** (a player at 44.1 kHz) while AES67 output
   runs. The tap is recreated at the new rate, as AirPlay's is, and the
   stream keeps its RTP timeline (no jump in timestamps). Test in Task 9
   (`a_new_master_rate_keeps_the_timeline`).
5. **Our own announcement and own multicast stream seen by our own SAP
   listener and input.** They are listed with `own: true` and cannot be
   selected, because playing our own output back would feed back. Test in
   Task 5 (`our_own_announcement_is_marked_and_not_selectable`).

- Produces:

  ```rust
                      pub rate: f64 /* ptp seconds per local second */ }
  pub struct Estimator { /* pure, no I/O */ }
  impl Estimator {
      pub fn new(domain: u8) -> Estimator;
      /// One packet off the wire: its source address, UDP port, payload and kernel receive time (CLOCK_REALTIME ns).
      pub fn packet(&mut self, from: std::net::Ipv4Addr, port: u16, payload: &[u8], rx_ns: i128);

  }

  impl PtpClock {
      pub fn off() -> PtpClock;
      pub fn now(&self) -> Option<PtpNow>;   // reads CLOCK_REALTIME itself
      pub fn generation(&self) -> u64;       // +1 on every grandmaster change or loss
  }
  ```
  `PtpClock` is read by the AES67 threads only, never by the audio thread,
  so a mutex is allowed.

- [ ] **Step 1: Write failing tests**, with synthetic packets from Task 2's
  builders and a simulated master running +16.3 ppm against local time,
  with ±20 µs receive jitter:
  - `locks_after_pairs_and_follows_the_rate`: after 8 s of 8 Hz
    Sync/Follow_Up, `now()` is `Some`. `rate` is within 0.5 ppm of the
    simulated value, and `ptp_ns` is within 50 µs of the truth.
  - `a_sync_without_its_follow_up_is_dropped`: pairing is by (source
    address, sequence). Unmatched Syncs are counted, never used.
  - `other_domains_and_one_step_are_ignored`.
  - `the_best_announce_is_followed`: two masters announcing; the better one
    by `better()` is followed, and Syncs from the other are ignored.
  - `a_better_master_takes_over_and_the_old_one_expires`: the followed
    master stops announcing for 3 intervals, or a better one appears. The
    estimator switches, discards its window, and `generation` changes.
  - `five_seconds_without_a_pair_is_none`.
  - `outliers_do_not_move_the_estimate`: one pair 2 ms late moves `ptp_ns`
    by less than 5 µs.
  - `a_local_clock_step_relocks`: `CLOCK_REALTIME` steps by +0.5 s (an NTP
    step). The window is discarded, `generation` changes, and the estimate
    locks again within 8 s instead of averaging across the step.
- [ ] **Step 2:** the tests fail.
- [ ] **Step 3: Implement.**
  - Offset = `origin_ns + follow_up.correction + sync.correction − rx_ns`.
  - Keep the last 16 s of (rx, offset) pairs.
  - Fit offset over local time by least squares after dropping pairs whose
    offset is more than 3 MAD from the median; the slope gives `rate`.
  - Stale-master expiry is 3 Announce intervals (log interval from the
    header; default 1 s).
- [ ] **Step 4:** the tests pass.
